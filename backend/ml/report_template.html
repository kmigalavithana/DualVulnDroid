04

Ablation Study

Isolating the contribution of each feature group within XGBoost, holding hyperparameters, split, and text vectorizers fixed.

Finding: concatenating the new security/data-flow features into XGBoost's training input did not improve — and on this test split, slightly hurt — raw multi-class accuracy versus the TF-IDF-only baseline. SHAP analysis (below) shows why: the model already recovers equivalent signal from character/word n-grams (e.g. the literal substring “rawquery”), so the explicit boolean feature is informative but largely redundant on this dataset size. The production model was still selected by validation macro-F1 (not test performance) per the documented methodology — it happened to be the data-flow config, which ties the full-hybrid config exactly on both val and test.

08

Limitations

  • Not a true application-level split. The raw dataset carries no app/project identifier, so leakage prevention is grouped by normalized-code template, not by which real app a line came from.
  • Small dataset for feature-level ablation. 791 training rows is not much for a tree model to learn robust splits on rare structural features — a larger corpus might show a different ablation result.
  • ML predictions are sensitive to exact formatting. The TF-IDF/count representation is not syntax-aware, so semantically-identical code split across lines differently can get different predictions — a known limitation vs. a true AST-based classifier.
  • Selective coverage. The hybrid decision engine currently auto-decides only ~35% of cases; the rest are deferred to SUSPICIOUS_REVIEW, which today maps to vulnerable=false for backward compatibility with clients that have no review-queue UI yet.
  • Single-line dataset rows. The multi-line sink-call fix in dataflow.py was necessary for real source files but could not be validated against this dataset, since every row is one line.
  • Data-flow analysis remains limited per its own documented scope: single-file, one-hop interprocedural, no reflection, no full Android call graph — not claimed as full-program analysis.
